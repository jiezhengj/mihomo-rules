# 适用对象

本契约定义本 Feature 交付的 Mihomo YAML 配置文件对模板使用者、维护者和目标 Mihomo 核心的可见要求。文件不是新增 HTTP API，也不定义新的 Mihomo 语法。

# 文件集合

- 公开模板：Desktop、Docker、iOS、Android × single、dual，共 8 份，采用项目规定的 `*_template.yaml` 命名，并可纳入版本控制。
- 个人配置：每个平台 1 份、无 `_template` 后缀的本地文件，共 4 份；必须被 `.gitignore` 忽略，不得暂存、提交或发布。
- Single 模式使用一个订阅占位符即可启动；dual 模式保留两个订阅源与用户可操作的独立机场切换能力。
- 公共说明只能描述占位符、策略行为、平台差异和经证实的资源来源；不得包含个人订阅、节点名、内网信息或个人专属策略组。

# 路由契约

- 路由意图按以下顺序判断：应拦截的流量走 `REJECT`；其余流量中不应代理的走 `DIRECT`；需要代理的非大流量走 `ROUTE_NORMAL`，需要代理的大流量走 `ROUTE_HEAVY`。业务规则只指向 `REJECT` / `DIRECT` / `ROUTE_NORMAL` / `ROUTE_HEAVY`，不得直接指向 `AUTO_*`。
- 候选链按配置类型区分，且只引用当前配置实际定义的策略组：
  - **4 份个人配置**：`ROUTE_NORMAL` 候选 `AUTO_STRICT → AUTO_GENERAL → AUTO_BACKUP`；`ROUTE_HEAVY` 候选 `AUTO_GENERAL → AUTO_STRICT → AUTO_BACKUP`。`AUTO_BACKUP` 恒在末位。
  - **8 份公开模板**：`ROUTE_NORMAL` 与 `ROUTE_HEAVY` 均 fallback 到单一 `AUTO` 组。模板用占位订阅，无法预设 `YOUR_HEAVY_KEYWORD` 节点命名，故不拆节点池。
- 公开双机场模板保留 `AUTO_1` / `AUTO_2` 作为 UI 独立逃生入口；个人配置不设这两组。`ROUTE_NORMAL` 名称不表示 AI 业务范围（原名 `ROUTE_AI` 已因语义脱节更名）。
- Desktop 游戏本体、补丁或分发切片下载按通用操作范围审阅 DIRECT 意图和规则组覆盖；商店、推荐、社区及营销请求不属于该下载操作。所有服务品牌适用相同判断，不另设品牌验收项或单服务规则。
- REJECT 路径须由维护者在规则设计记录中点名代表场景并说明屏蔽依据。
- 未被更具体规则处理的流量最终经 `PROXY`。该兜底必须是每份配置规则序列的最后一项。
- 业务规则不得直接指向 `AUTO_XXX`。交叠时须记录具体场景的首匹配预期；集合名本身不能证明用途。

# 规则数据契约

- 每个资源声明与引用成对存在，记录固定上游来源、revision、路径、匹配对象/行为、格式及适用限制；代表成员审阅须标明范围和抽样边界。
- 资源选择遵循“原则性”：按已确认意图优先采用覆盖最完整且边界适用的资源，不因服务知名或名称熟悉而默认引入 Apple、Google 等细分资源。只有具体证据表明不应代理流量进入代理、非大流量代理操作进入 `ROUTE_HEAVY`、或大流量代理操作进入 `ROUTE_NORMAL`，并且调序无法解决或会引入新的路由问题时，才考虑更细资源；候选形态不限于规则集。门槛证据须可追溯到具体操作及意图、资源成员和匹配语义、当前首匹配规则/动作与预期动作；另记录拟调整的顺序、其不能消除此误分流或造成其他误分流的具体场景。样本审阅不得描述为全量覆盖证明。每个新采用资源有具体意图依据、代表性成员证据和混合用途/覆盖边界说明。
- 规模分类针对具体代理操作。场景记录须说明预期传输特征（如批量载荷、长时媒体或实际承载图片/视频的 CDN 操作）、分类理由和依据来源；仅凭服务名、CDN 身份或集合名不足以定类。契约不设数值吞吐/字节阈值，也不要求运行时按流量切换；依据不足的操作须标为待确认。
- 已知精确交集、后缀匹配重叠或 CIDR 包含关系须注明检查方法及其范围限制。
- 不适用于单一动作或含有明显反向用途的集合不得整体赋予该动作；缺口通过规则组级方案记录，不通过新增单服务例外隐藏。
- 若实现采用内置 GeoSite/GeoIP 数据库而非独立 provider，说明相应数据库构建/更新来源与目标核心支持版本，不得声称它等价于未检查的独立资源。

# 平台与私有边界

- 8 个公开模板的通用策略和场景规则同构；允许的差异限于宪章指定的平台设备边界与订阅模式，并记录原因。
- iOS 使用项目要求的负向先行断言兼容节点过滤写法；iOS 与 Android 遵守移动端规则裁剪。
- Desktop 保留适用桌面能力；Docker 不启用 TUN、限制监听端口并启用 Sniffer。
- Tailscale、UU 远程和绿联 NAS 等个人用途规则仅存在于适用平台的本地个人配置，不进入公开模板。
- iOS Network Extension 15 MB 是运行时资源约束；未完成有明确客户端、环境、指标和步骤的设备测量时，契约状态必须写作待验证，不得从配置解析或文件体积推断符合性。

# 兼容性与验证

- 配置必须由交付时声明的 Mihomo 核心版本解析通过。核心升级时重新核对 YAML 结构、provider 格式及规则语义。
- Mihomo 配置解析通过是语法/结构检查，不代表任意目标域名一定由预期规则匹配。
- 每个已确认场景需审阅首次匹配到的规则及动作；未确认成员不得标为已通过。
- 任何通用路由行为变化必须同步复核全部 8 份公开模板及适用个人配置。
