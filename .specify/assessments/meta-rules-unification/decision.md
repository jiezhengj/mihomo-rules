- **标识符**：meta-rules-unification
- **决策日期**：2026-10-03（Asia/Hong_Kong）
- **结论**：go
- **审阅产物**：intake.md、research.md、problem.md、concept.md

## 评估

| 评估标准 | 评级 | 理由 |
|-----------|--------|---------------|
| 问题有效性 | adequate | 用户明确希望新规则按常见流量意图重写，使用四类去向：小流量翻墙、大流量翻墙、直连和屏蔽，并以 `PROXY` 兜底。 |
| 证据强度 | adequate | 已研究 MetaCubeX 数据形态、Mihomo 行为及旧配置汇总现状；这些证据支持继续定义方向，但新场景覆盖、流量边界与动作优先级仍待后续核实。 |
| 价值相对不行动 | adequate | 以简单、明确的流量意图重组路由符合维护者的常见使用场景；若继续沿用旧分类逐项组织会偏离已说明的目标。 |
| 可行性 / 投入匹配 | adequate | 概念方向明确，12 份配置的实际重建和平台差异仍需后续定义；小/大流量判断及边缘场景需在规范阶段收敛。 |
| 战略契合 | adequate | 使用 MetaCubeX 发布的公开资源符合用户指定方向；需在说明中准确保留其资源可能汇集其他上游数据的事实。 |
| 风险姿态 | adequate | 主要风险包括“小流量/大流量”边界、重叠集合首匹配、Epic 既有期望与新意图可能冲突，以及平台资源占用；已识别但尚未全部裁定。 |

## 结论和理由

结论为 `go`：可以将新规则重写交给 Feature SDD 明确行为规范。方向已确定为从常见流量意图出发，分为需翻墙的小流量（`ROUTE_AI`）、需翻墙的大流量（`ROUTE_GLOBAL`）、不应翻墙（`DIRECT`）和应屏蔽（`REJECT`），最后由 `PROXY` 兜底；`rule-providers` 之前的内容可参考旧配置重建，而新规则不逐项映射旧 provider。research 中的旧配置汇总仅提供历史证据和风险背景，不能转成替换清单或新规则输入。进入 Feature 前后需确认流量大小边界、规则重叠时的动作次序、Epic 的新路由意图、平台资源影响和私有配置处理。MetaCubeX 发布的数据可能汇集其他上游，相关说明应准确表述资源的发布来源和汇集情况。
