# Mihomo (Clash Meta) 精细化白名单路由配置模板

这是一个专为 Mihomo (Clash Meta) 设计的高阶配置文件集合。包含了分别针对桌面端 (Desktop)、Android、iOS 客户端以及 Docker 代理容器的专属**配置模板**。本仓库的设计初衷是提供一套**极度干净、可控且智能**的网络分流体系。

## 设计思路：白名单模式与强制兜底

本配置模板的核心哲学是 **“白名单模式 (White-list)”**：
1. **预设明确直连：** 局域网、国内 IP (基于 GeoIP)、国内域名 (基于 GeoSite)、以及特殊应用直连。
2. **预设明确拦截：** 针对特定的广告、隐私追踪（基于 Reject 规则集），以及特殊的抗干扰需求（如拦截 QUIC 以避免浏览器 UDP 穿透直连）。
3. **未匹配的统一走代理：** 在规则的最末尾设置 `- MATCH,PROXY` 作为兜底。只要不是明确直连的流量，全部送入代理。这避免了日常“漏网之鱼”导致的网络阻断，完美解决各类小众国外网站、冷门客户端无法连通的问题。

## 为什么自己拉取远程规则集，而不是用机场自带的配置？

很多人习惯直接复制机场（服务商）提供的订阅链接，导入 Clash 后直接使用。但这存在巨大的弊端，自己编写配置文件并挂载远程规则集具有不可替代的优势：

1. **摆脱服务商的乱配与臃肿**：很多服务商的默认配置多年未更新，规则堆砌上万条，极大地消耗内存，甚至写错路由逻辑（比如把测速节点当成常规节点、错误放行导致隐私泄露）。
2. **随时拥抱最新的规则数据库**：我们使用了 `rule-providers` 动态拉取如 Loyalsoldier 等维护的开源规则集（如 `gfw.txt`, `telegramcidr.txt`），甚至针对特定的 CDN (如 Cloudflare) 拉取 IP 规则。这确保了哪怕域名被污染或伪装，底层的 IP CIDR 依然能准确匹配分流。机场永远不会像开源社区一样每日勤奋更新这些规则。
3. **掌控权在自己手里**：您可以自由组合多个机场，或者实现特定的网络魔法（比如强制让特定应用走某个特定节点），而这些在单纯依赖机场订阅时是无法实现的。

## 如何使用本模板（配置您的订阅）

本仓库中的 `*_template.yaml` 文件是去除了私人信息的通用模板。您**唯一需要做的事情**，就是把您的机场订阅链接填进去。

打开您需要的配置模板（例如 `mihomo_config_desktop_template.yaml`），找到 `proxy-providers` 部分。

### 场景一：单机场（大多数人）
找到名为 `sub_nodes_1` 的配置块，将 `url` 后面的占位符替换为您自己的订阅链接。
```yaml
proxy-providers:
  sub_nodes_1:
    type: http
    url: "在此处粘贴您的机场订阅链接"
    # 其他保持默认...
```

### 场景二：双机场 / 多机场组合
如果您购买了多个机场，或者有免费的备用订阅。您可以直接在下面追加 `sub_nodes_2`、`sub_nodes_3`。
```yaml
proxy-providers:
  sub_nodes_1:
    type: http
    url: "您的主力机场链接"
    # ...
  
  sub_nodes_2:
    type: http
    url: "您的备用机场链接"
    # ...
```

如果您添加了新的 `sub_nodes_2`，为了能在界面上选用，请顺便往下滑动到 `proxy-groups` 的最下方 `ALL_NODES` 分组中，将 `sub_nodes_2` 引入，这样您的备用节点就能和主力节点一起参与测速和智能选择了：
```yaml
  - name: ALL_NODES
    type: select
    use:
      - sub_nodes_1
      - sub_nodes_2  # <--- 添加这一行
```

## 注意事项与优化点
- **QUIC 阻断降级**：我们在所有涉及到 TUN 拦截的配置（Desktop, Android, iOS）顶部添加了拦截 UDP 443 端口的规则。这能强制 Chrome 等浏览器放弃不稳定的 HTTP/3 并无感降级到 TCP，彻底根除观看流媒体断流、视频缓冲等代理穿透问题。
- **嗅探 (Sniffer)**：在移动端和桌面端强制开启了协议嗅探。应对部分浏览器基于 DoH 绕过本地 DNS 发起裸 IP 连接时，Mihomo 能强行还原出域名并参与规则匹配。
